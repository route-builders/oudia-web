# プロジェクト定義 — ゴールとスコープ

本書は OuDiaSecond Web 再実装プロジェクトの定義書である。技術的な設計判断は `docs/design/02_architecture.md`(以下「アーキテクチャ設計」)に、機能の棚卸しは `docs/analysis/08_manual-features.md`(以下「機能インベントリ」)に依拠する。

---

## 1. 背景

### 1.1 系譜

| ソフトウェア | 作者 | 期間 | 概要 |
|---|---|---|---|
| **OuDia** | take-okm 氏 | 2006–2017(〜Ver1.02.05) | 列車時刻表からダイヤグラム(列車運行図表)を描く Win32 アプリケーション。GPLv3(or later)で公開 |
| **OuDiaSecond** | diagram_mania 氏 | 2017–現在(ver2.06.23 時点) | OuDia の改造版。秒単位時刻・番線・在線表・運用機能・交差支障チェック等を拡張し、独自形式 .oud2 を導入。GPLv3 派生物 |
| **本プロジェクト** | — | 2026– | OuDiaSecond ver2.06.23 相当の機能を Web アプリケーションとして再実装する。GPLv3 派生物 |

OuDia / OuDiaSecond は、鉄道ダイヤ作成愛好家コミュニティの事実上の標準ツールであり、.oud / .oud2 形式で蓄積された膨大なファイル資産が存在する。

### 1.2 動機 — なぜ Web 再実装か

原典は MFC ベースの Windows 専用アプリケーションであり、次の制約がある。

1. **Windows でしか動かない。** macOS・Linux・タブレット・スマートフォンでは利用できず、「作ったダイヤを外出先で見る」ことすらできない。
2. **インストールが必要。** 配布・更新は zip の手動展開であり、試用の敷居が高い。
3. **技術基盤の持続性。** MFC / GDI / Visual Studio という技術スタックは新規開発者の参入障壁が高く、長期の保守継続に不安がある。

一方で、原典の**機能・操作体系・ファイル形式は成熟しており、再設計の必要はない**。したがって本プロジェクトは「新しいダイヤ作成ソフトを作る」のではなく、「OuDiaSecond をそのままブラウザに持ってくる」ことを目指す。既存ユーザがファイルも操作の記憶もそのまま持ち込めることが最大の価値である。

## 2. ゴールと非ゴール

### 2.1 ゴール

1. **インストール不要**: ブラウザを開けば使える。PWA として初回訪問後は完全オフラインで動作する(アーキテクチャ設計 §8.2)。
2. **ファイル資産の完全継承**: .oud2(書き出しは現行 1.17)の読み書き**バイト互換**。旧世代 .oud2(1.00–1.16)および OuDia .oud の読み込み互換。Windows 版と同じファイルを往復編集しても壊れない(§4)。
3. **操作体系の継承**: 時刻表ビューのキーボード操作(連続入力モード・Ctrl+J/K/L・ピリオド再実行等、機能インベントリ §4)を再現し、既存ユーザが再学習なしで移行できる。
4. **Web らしい価値の追加**: スマートフォン・タブレットでの閲覧、OS を問わない編集、OPFS 自動バックアップによる「保存し忘れてもデータが残る」体験。
5. **クライアント完結**: サーバを必要としない。ファイルはローカルで読み書きし、ユーザのデータがユーザの手元から出ない。
6. **段階的リリース**: v0.1(ビューア)から単独で価値を持つ 8 段階のリリース(§5)により、個人開発でも各段階で成果を公開できる。

### 2.2 非ゴール

以下は**やらない**と明確に決める。

| 非ゴール | 理由 |
|---|---|
| ダイヤ作成ソフトとしての再設計・独自進化(初期段階) | 原典との同一性こそが価値。UI 改善は操作体系を壊さない範囲に限る |
| サーバサイド機能(アカウント・クラウド保存・共同編集) | クライアント完結が原則。将来拡張の**余地**として patch 方式 Undo(操作ログ化可能)を採るに留める |
| .oud2 形式の独自拡張(新キーの追加) | Windows 版との相互運用を壊す。ファイル形式のオーナーシップは原典側にある |
| WinDIA(.dia)入出力 | OuDiaSecond 自身が Ver1.02 で削除済み |
| 外部時刻表インポート(JR 東日本・おでかけネット・JR 北海道) | 事業者サイト構造依存でスクレイピング的。法的にも別検討が必要 |
| 多言語対応(i18n) | UI は日本語のみ。原典ユーザ層に一致 |
| ネイティブアプリ(Electron 等)としての配布 | PWA で代替する |
| MDI ウインドウ整列・CHM ヘルプ・ini 設定ファイル等の Windows 固有 UI の再現 | Web の流儀(タブ・localStorage)に置き換える |

## 3. 対象ユーザ

優先順に:

1. **既存の OuDiaSecond ユーザ**(最優先)。番線・運用機能まで使い込む上級者を含む。移行の判断基準は「自分の .oud2 が壊れないこと」「手に馴染んだキーボード操作が動くこと」。
2. **既存の OuDia ユーザ**。.oud 資産の読み込みと、.oud 互換書き出し(機能喪失警告付き)で受け入れる。
3. **閲覧のみのユーザ**。作成者から共有された .oud2 をスマートフォンで開いて時刻表・ダイヤグラムを見る(v0.1 の単独価値)。Windows を持たないこの層は原典が取りこぼしてきたユーザである。
4. **新規ユーザ**。インストール不要により試用の敷居が下がる。ただし初期段階では原典の操作体系を前提とし、チュートリアル整備は後回しとする。

## 4. 互換性要件

互換性は本プロジェクトの**最上位制約**である(アーキテクチャ設計 §1.1)。

### 4.1 .oud2 読み書き(バイト互換)

- 現行リーダーの対象である **OuDiaSecond.1.10〜1.17** 形式の読み込みと、**1.17** 形式での書き出しをサポートし、**「読込 → 無編集 → 書出」で元ファイルとバイト一致**させる。これを CI の必須ゲートとする(v0.2 以降、アーキテクチャ設計 §7.1)。
- ただし最終行の **FileTypeAppComment のみ例外**とし、書き出し時は常に自アプリ名で再生成する(読込で未使用であり、原典自身も保存時に自版名へ書き換えるため)。黄金テストでは元の値を注入して**完全バイト一致**で検証する(ファイル I/O 設計 `04_file-io.md` §4.3–§4.4)。
- 出力規則(true のみ出力・非デフォルト時のみ出力・キー出現順・時刻書式・COLORREF 16 進表記等)は分析 §03 の仕様表に基づきテーブル駆動で実装する。
- **未知キー・未知ノードは保持して書き戻す**。将来版 OuDiaSecond で作られたファイルを開いて保存しても情報を失わない。
- **WindowPlacement ノード**(oud2 内に保存される Windows 版のウインドウ配置)は Web 版では利用しないが、読込時に保持し書き出し時に透過的に書き戻す。**Windows 版と往復してもファイルを壊さない。**

### 4.2 旧世代 .oud2 / .oud の読み込み

- 旧世代 oud2(1.00–1.16)のうち **1.00–1.09** を世代別リーダー(S00 = 1.00 / S05 = 1.01–1.05 / S09 = 1.06–1.09)で読み込む。**1.10–1.16** は現行リーダー(1.10–1.17 対応、§4.1)が担当する(分析 `03_file-format.md` §4)。
- OuDia .oud(FileType=OuDia.1.02、Shift_JIS)を読み込む。旧駅扱 3(経由なし)→ 0 変換、Kyoukaisen(境界線)からの分岐推定等の世代差分変換を含む。
- 原典の**寛容読込規則**(非数 → 0、範囲外 index → 主本線補正、SJIS 0x5C 救済ハック)を再現し、原典で開けるファイルは本アプリでも開ける。

### 4.3 .oud 互換書き出し

- FileType=OuDia.1.02 の最小キー集合で Shift_JIS 書き出しをサポートする(番線・運用等は喪失)。保存前に原典と同文言の機能喪失警告を出す。

### 4.4 挙動互換

ファイルだけでなく**見た目と挙動**も互換対象とする。

- ダイヤグラムのレイアウト(駅間最小所要秒数・スジの折れ線分割・ラベル位置)は原典アルゴリズムの忠実移植(`computeDiagramLayout`)。
- 時刻表の表示書式(「ﾚ」「||」「・・」「----」「○」等の記号、種別別フォント・色)。
- 運用探索は「Windows 版と同一入力 → 同一の運用表内容」を比較テストで保証する。

## 5. スコープ

機能インベントリの Tier 分類(§9)とアーキテクチャ設計のリリース段階(§3.5)に基づき、次の通り線を引く。

### 5.1 初期リリース(v0.1〜v0.4)に含む機能

**v0.1〜v0.2 = Tier1 のうち閲覧・ファイル I/O、v0.3〜v0.4 = Tier1 の列車編集(Undo/Redo 含む)+ Tier2(入力効率)** に対応する(Tier1 の構造編集残りは v0.5。機能インベントリ §9)。ここまでで「運用機能を使わないユーザの日常編集」が原典同等になる。

| バージョン | 含む機能 |
|---|---|
| **v0.1 ビューア** | oud2(全世代)/ oud の読込。時刻表・ダイヤグラム・駅時刻表の**閲覧**。路線ツリー・タブ。PWA オフライン。モバイル閲覧 |
| **v0.2 ラウンドトリップ保存** | 無編集完全再保存(バイト一致 CI ゲート稼働)。.oud 互換書き出し(機能喪失警告付き、§4.3)。時刻表 CSV・駅時刻表 CSV 書き出し。コメント編集。OPFS 自動バックアップ(編集契機 60 秒)+ クラッシュ復元。互換セルフチェック機能(開く → 保存 → 差分ゼロ確認。FileTypeAppComment 行は正規化して除外、§4.1) |
| **v0.3 列車編集** | 列車のプロパティ・駅時刻ダイアログ。列車の挿入・消去。列単位カット/コピー/ペースト(貼り付け移動量によるパターンダイヤ連続貼り付け含む)。Undo/Redo(patch 方式、深さ既定 100)。時刻のみ貼り付け |
| **v0.4 入力効率** | 連続入力モード(Ctrl+T)、時の補完、繰上げ/繰下げ連動、連続 1 分修正(Ctrl+J/K/L 系 6 コマンド)、駅時刻変更 + 再実行(ピリオド)、通過/停車トグル、当駅止り/当駅始発/分断/直通化(3 方式)/列車番号で一本化、並べ替え(4 方式)、フォーカス移動モード、最小所要時間列車に移動、列車番号検索。キーマップ設定(ブラウザ予約衝突の代替バインド含む)。Playwright キーボード回帰テスト |

### 5.2 後続リリース(v0.5〜v0.8)に含む機能

Tier1 の構造編集残りと **Tier3(OuDiaSecond 差別化機能)**。依存順(番線 → 運用 → 箱ダイヤ)に段階導入する。

| バージョン | 含む機能 |
|---|---|
| **v0.5 構造編集** | 駅・種別・ダイヤの編集(挿入・削除・入替・反転)と整合カスケード(index 再マップ・分岐環状 adjust)。駅・種別・路線・ダイヤの各プロパティ。分岐駅・環状線・反転駅設定。路線ファイルの組入れ/切り出し。時刻表 CSV 読み込み(書き出しは v0.2) |
| **v0.6 番線系** | 駅番線・主本線・列車番線・番線編集モード。在線表(ダイヤグラム)。カスタマイズ時刻表(市販時刻表風表示) |
| **v0.7 運用機能** | 駅作業(入換・増解結・出入区・路線外発着・前後列車接続)、運用探索(Worker 実行)、運用表・運用一覧・運用一覧図・箱ダイヤ、入出区連携コード一覧、基準運転時分、運用表 CSV |
| **v0.8 以降** | 交差支障チェック、パターンダイヤプレビュー、運休扱い列車・隠し種別、印刷仕上げ(ページ分割 PDF)、静的リンク共有 |

### 5.3 含まない機能(恒久)

§2.2 の非ゴールに対応: WinDIA 入出力 / 外部時刻表インポート / CHM ヘルプ / MDI ウインドウ整列 / ini・レジストリ設定 / ウインドウ配置の復元(ファイル内 WindowPlacement は透過保持のみ)/ サーバ機能。

### 5.4 Web 版で仕様を置き換えるもの

| 原典 | Web 版 | 根拠 |
|---|---|---|
| MDI 子ウインドウ + アクティブビュー連動メニュー | タブ + ビュー種別ごとのメニュー/ツールバー | 機能インベントリ §10.2 |
| 印刷(MFC 印刷パイプライン・プリンタ設定) | ブラウザ印刷 / PDF(v0.8) | Tier4 |
| .ini へのビュー設定永続化 | localStorage | アーキテクチャ設計 §4.5 |
| 自動バックアップ(実行ファイル隣接ディレクトリ) | OPFS 世代保存 + クラッシュ復元 | アーキテクチャ設計 §6.3 |
| OS クリップボード独自フォーマット | アプリ内クリップボード + テキスト形式互換 | 機能インベントリ §10.4 |
| Undo 深さ 8 固定 | 既定 100・設定可変 | アーキテクチャ設計 §4.4 |

## 7. 成功基準

各リリースの「完成」を判定できる基準を定める。

### 7.1 互換性(v0.2 で達成、以後維持)

- [ ] sample2.oud2 を含む互換テストコーパス全ファイルで「読込 → 無編集 → 書出 → **バイト一致**」を CI が常時検証し、100% 通過している(FileTypeAppComment 行のみ例外。テストでは元の値を注入して完全一致で検証する。§4.1)。
- [ ] 旧世代ファイル(1.00–1.16 / OuDia.1.02)の「読込 → 1.17 書出」結果が、Windows 版 OuDiaSecond による変換結果と一致する。
- [ ] Windows 版で作成 → Web 版で編集・保存 → Windows 版で再度開く、の往復で警告・データ欠損が発生しない(WindowPlacement 含む)。

### 7.2 性能(アーキテクチャ設計 §8.1 の数値目標)

- [ ] 500 列車 × 50 駅のベンチマークフィクスチャで、ダイヤグラム・時刻表グリッドのスクロール/ズームが 60fps、編集反映 16ms 以内、数 MB 級 oud2 の読込 1 秒以内。CI で継続測定。

### 7.3 操作互換(v0.4 で達成)

- [ ] 原典マニュアル 2.3 章「列車のいろいろな入力方法」の全操作が Playwright E2E で再現・通過している(PWA インストール時/ブラウザタブ時の両キーマップ)。

### 7.4 提供形態

- [ ] 初回訪問後、機内モードで全機能(ファイルを開く・編集・保存)が動作する。
- [ ] iOS Safari / Android Chrome で .oud2 を開き時刻表・ダイヤグラムを閲覧できる(v0.1)。
- [ ] クラッシュ・タブ誤クローズ後の再訪で、直近のバックアップ時点の編集状態が復元できる(v0.2)。バックアップは編集コマンド契機・60 秒間隔(アーキテクチャ設計 §6.3)であり、失われる編集は直近バックアップ以降のものに限る。

### 7.5 コミュニティ(定性)

- [ ] 既存 OuDiaSecond ユーザによる実ファイルでの互換レポート(§4.1 のセルフチェック機能経由)が集まり、報告された非互換がゼロに収束していること。
- [ ] GPLv3 の義務(ソース公開・クレジット表示)がリリース物すべてで満たされていること。
