# UI・画面設計

本書は OuDiaSecond Web 再実装の UI・画面設計書である。`docs/design/02_architecture.md` で確定した技術スタック(React 18 シェル + Canvas グリッド/ダイヤ描画、ネイティブ `<dialog>` + `usePropEdit`、Zustand + Immer patch Undo、ビュー記述子ベースのタブ管理)を前提に、各画面のレイアウト・表示要素・操作仕様を確定する。

原典ビューの仕様詳細は分析ドキュメント(§04 時刻表、§05 ダイヤグラム、§06 その他ビュー、§07 運用・交差支障、§08 機能インベントリ)を一次情報とし、本書では「Web でどう構成するか」の決定のみを記す。

---

## 1. 画面構成の全体像

### 1.1 アプリケーションシェル

原典の「左ペイン = 路線ビュー(ツリー) + 右ペイン = MDI 作業領域」を、Web では**左サイドバー + タブ型単一作業領域**に写像する。MDI の重ね表示・並べて表示は採用しない(タブ切替 + ビュー間相互ジャンプで代替。左右分割ペインは将来拡張とし本設計の範囲外)。

```
+----------------------------------------------------------------------+
| メニューバー: ファイル 編集 表示 [ビュー固有メニュー…] ウインドウ ヘルプ |
+------------+---------------------------------------------------------+
| 路線ツリー  | タブバー: [平日 下り時刻表][平日 ダイヤグラム][駅] … [×] |
| (サイドバー)+---------------------------------------------------------+
| ▸ ○○線     | ビューツールバー(アクティブビュー固有のトグル・操作)      |
|   ├ 駅     +---------------------------------------------------------+
|   ├ 列車種別|                                                         |
|   ├ ダイヤ  |          アクティブビュー本体                            |
|   │ └ 平日 |          (Canvas グリッド / Canvas ダイヤグラム /        |
|   │   ├ …  |           textarea 等)                                  |
|   └ コメント|                                                         |
+------------+---------------------------------------------------------+
| ステータスバー: 変更状態 | モード | 貼り付け移動量 | 基準運転時分差 | 通知 |
+----------------------------------------------------------------------+
```

構成要素の責務:

| 要素             | 実装                                              | 内容                                                                                                                                                                                                     |
| ---------------- | ------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| メニューバー     | React(WAI-ARIA menubar パターン、roving tabindex) | 原典メニューの全コマンド。アクティブビューの種類に応じてビュー固有メニュー([時刻表][駅時刻][表示]等)を**差し替え表示**する(原典の動的メニューを踏襲)。各項目にショートカットキーを併記                   |
| 路線ツリー       | React(自前ツリー、`role="tree"`)                  | 原典 CDlgRosenView と同構造(§1.5)。ナビゲーション専用で編集機能なし                                                                                                                                      |
| タブバー         | React                                             | ビュー記述子をキーとするタブ列。閉じるボタン、中クリックで閉じる、ドラッグで並べ替え                                                                                                                     |
| ビューツールバー | React                                             | アクティブビュー固有の表示トグル・ズーム・検索。原典ツールバー相当                                                                                                                                       |
| ビュー本体       | Canvas(render パッケージ)+ IME オーバーレイ input | §3 参照                                                                                                                                                                                                  |
| ステータスバー   | React(ストア購読)                                 | 変更状態(未保存 `*`)、編集モード(連続入力中等)、貼り付け移動量(クリックでビューのプロパティを開く。原典のダブルクリック導線を踏襲)、基準運転時分差、運用探索中インジケータ、通知(自動バックアップ完了等) |

### 1.2 タブ管理(原典 MDI の写像)

- タブは**ビュー記述子**をキーに管理する(02_architecture §4.5)。同一記述子のタブは二重に開かず、既存タブをアクティブ化する(CHidemdiDoctmplDocstrAlone 相当)。
- ダイヤ削除・改名、駅削除時は、ストア購読でビュー記述子の整合性を検証し、無効になったタブを自動クローズする(原典 UpdateAllSubDocviews 相当)。
- ビュー記述子の型定義(apps/web):

```typescript
type ViewDescriptor =
  | { type: 'eki' }
  | { type: 'syubetsu' }
  | { type: 'comment' }
  | { type: 'jikokuhyou'; diaName: string; houkou: 0 | 1; customize: boolean }
  | { type: 'diagram'; diaName: string }
  | { type: 'ekiJikokuhyou'; diaName: string; houkou: 0 | 1; ekiIndex: number }
  | { type: 'ekiJikokuhyouList'; diaName: string }
  | { type: 'operationTable'; diaName: string; operationNumber: string } // v0.7
  | { type: 'allOperationTable'; diaName: string; graphical: boolean } // v0.7(表/図)
  | { type: 'crossingCheck'; diaName: string; ekiIndex: number } // v0.8
  | { type: 'inOutLinkCodeList'; diaName: string }; // v0.7
```

- ダイヤ参照は原典同様**名前照合**(diaName)。駅参照のみ index(原典 DocStr「ダイヤ名\n方向\n駅Index」と同型)とし、駅編集コマンド実行時のタブ整合検証で追随・クローズする。
- タブのアクティブ化は原典の「保留された全更新の実行」(m_bUpdate_All_Requested)を踏襲する: 非アクティブタブのビューは再描画せず、コマンド型ヒントだけ蓄積し、アクティブ化時にまとめて再構築する。
- 非表示タブの Canvas は破棄可能とする(ビューモデル = ビュー記述子 + 表示トグルのみ保持し、再表示時に derive から再構築する)。数十タブ開いてもメモリを消費しない。

### 1.3 メニュー体系

原典のメニュー構成をほぼそのまま踏襲する。Windows 固有項目のみ置換する。

| メニュー     | 内容                                                                                                                                                                                                                                 | 原典からの変更                                                                                                     |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------ |
| ファイル     | 新規作成(v0.5〜)/開く/最近使ったファイル/上書き保存/名前を付けて保存/oud 形式で書き出し/CSV エクスポート・インポート/路線ファイルのプロパティ/ダイヤ一覧/路線ファイルの組入れ・切り出し(v0.5)/互換セルフチェック(開く→保存→差分確認) | 印刷はブラウザ印刷に委譲(v0.8)。「アプリケーションの終了」削除。「互換セルフチェック」を新設(02_architecture §6.4) |
| 編集         | 元に戻す/やり直し/切り取り/コピー/貼り付け/時刻のみ貼り付け/消去/すべて選択/作業のコピー/列車情報のコピー/検索・次を検索・置換(コメントビュー時、§3.5)                                                                               | Undo 項目にコマンド名を表示(「元に戻す: 列車の編集」)                                                              |
| 表示         | アクティブビューの表示トグル群(§3 各節)                                                                                                                                                                                              | .ini → localStorage                                                                                                |
| (ビュー固有) | [時刻表][駅時刻](時刻表ビュー時)、[ダイヤグラム](ダイヤ時)等                                                                                                                                                                         | 原典と同一コマンド構成                                                                                             |
| ウインドウ   | 次のタブ/前のタブ/タブを閉じる/すべて閉じる                                                                                                                                                                                          | MDI 整列コマンドは削除                                                                                             |
| ヘルプ       | 操作ガイド(アプリ内 HTML)/キーボードショートカット一覧/バージョン情報(GPLv3・原著作者クレジット・ソースリポジトリへのリンク)                                                                                                         | CHM → アプリ内ページ                                                                                               |

メニューコマンドの有効/無効は、原典の `bQueryEnable` 二相呼び出しの代わりに、アクティブビューのビューモデルが公開する `canExecute(commandId): boolean` 導出値で制御する(分析 §04 10.4)。

### 1.4 URL ルーティング

クライアント完結・ローカルファイル前提のため、**URL はファイルを表現しない**。URL ハッシュには「アクティブタブのビュー記述子」のみをシリアライズし、リロード・ブックマーク・戻る/進むに対応する。

- ルータライブラリは使わず、`hashchange` と UI ストアの双方向同期を自前実装する(約 100 行)。
- ルート一覧(ダイヤ名は `encodeURIComponent`):

```
#/                                        ホーム(ファイル未オープン)
#/eki                                     駅ビュー
#/syubetsu                                列車種別ビュー
#/comment                                 コメントビュー
#/dia/{diaName}/jikokuhyou/{kudari|nobori}
#/dia/{diaName}/jikokuhyou-c/{kudari|nobori}      カスタマイズ時刻表
#/dia/{diaName}/diagram
#/dia/{diaName}/eki-jikokuhyou/{kudari|nobori}/{ekiIndex}
#/dia/{diaName}/eki-jikokuhyou-list
#/dia/{diaName}/operation/{operationNumber}        v0.7
#/dia/{diaName}/all-operation                      v0.7(一覧表)
#/dia/{diaName}/all-operation-zu                   v0.7(一覧図)
#/dia/{diaName}/crossing-check/{ekiIndex}          v0.8
#/dia/{diaName}/inout-link-code                    v0.7
```

- ブラウザの戻る/進む = タブのアクティブ切替(タブの開閉はしない)。ハッシュが指すタブが未オープンなら新規に開く。
- リロード時: ファイル内容は URL から復元できないため、(1) File System Access API のハンドル(idb 永続化)があれば再オープンを提案、(2) なければ OPFS 自動バックアップからの復元を提案し、承諾後にハッシュのビューを開く。

### 1.5 路線ツリー

原典 CDlgRosenView のツリー構造を踏襲しつつ、右クリック限定だった隠し導線(運用一覧図・入出区連携コード一覧)は**常設の子項目に昇格**する。

```
[路線名]                        クリック=選択 / ダブルクリック・Enter=路線ファイルのプロパティ
 ├ [駅]                        クリックで駅ビュー
 ├ [列車種別]                  クリックで種別ビュー
 ├ [ダイヤ]                    ダブルクリック・Enter=ダイヤ一覧ダイアログ
 │  └ [(ダイヤ名)] × n
 │     ├ [下り時刻表]          ダイヤ別名があれば「(別名)時刻表」
 │     ├ [上り時刻表]
 │     ├ [ダイヤグラム]
 │     ├ [下りカスタマイズ時刻表]   v0.6〜表示
 │     ├ [上りカスタマイズ時刻表]   v0.6〜表示
 │     ├ [駅時刻表一覧]
 │     ├ [運用一覧表]              v0.7〜 ※
 │     ├ [運用一覧図]              v0.7〜 ※(原典の右クリック導線を常設化)
 │     └ [入出区連携コード一覧]     v0.7〜 ※(同上)
 └ [コメント]                  クリックでコメントビュー
```

- ※ 印の 3 項目([運用一覧表][運用一覧図][入出区連携コード一覧])は **EnableOperation=2(通常モード)時のみ表示**する(原典の[運用一覧]ツリー項目と同条件。分析 §07 3.2。簡易モード =1 では運用番号が割り当てられないため成立しない)。
- 実装済みリリース段階に存在しない項目はツリーに出さない(グレーアウトでなく非表示)。
- キーボード操作: 矢印で移動、Enter で開く、`*` で全展開(標準 tree パターン)。

- **固定領域**: 左 2 列(駅名 + 着発見出し)と上部ヘッダ行群(列車番号〜終着駅作業。運用モード・表示設定で行数可変)。原典 `setXFixColumnCount(2)` / `setYFixColumnCount` を踏襲。
- **行・列の意味対応**は原典 ColSpec 方式(X = [0:駅名, 1:着発, 2..:列車, 末尾:新規列車]、Y = ヘッダ部 + 駅ごと[入線/着/前作業/番線/後作業/発] + 路線外終着/備考)を `derive` の `colSpec`/`rowSpec` 純関数として移植。非表示行への参照は代替行に解決する(ColumnNumberFromSpec 相当)。行の有無 = 駅プロパティ(駅時刻形式・番線表示)× ビュートグル([全時刻を表示][通過駅の駅時刻を表示])。番線行の表示・編集は v0.6〜(02_architecture §3.5)。

- **表示トグル**(ツールバー [表示▾]、localStorage 永続化): 通過駅の駅時刻を表示(既定 ON)/全時刻を表示/秒表示/コロン表示/始発・終着駅名欄/親種別表示/通過に種別フォント/基準運転時分機能/運用更新一時停止(v0.7)/繰上げ繰下げ/並べ替え方式/末尾要素基準。

#### 編集操作(列車編集モード)

原典 CWjkState_Ressyahensyu の仕様をそのまま踏襲する。

1. **文字・数字キー押下 → フォーカス行に応じたダイアログを初期文字列付きで開く**(CKeyinputSenderToModalDlg の代替、§5.2)。セル直接タイプは存在しない。
2. どのダイアログが開くか(ダブルクリック・Enter も同じ): 駅名列上 → 駅のプロパティ / 駅時刻・番線行 → 駅時刻のプロパティ / 作業行 → 作業のプロパティ / 列車プロパティ行 → 列車のプロパティ / 運用番号行 → 運用表へ移動。Alt+Enter は作業を優先。
3. フォーカスが新規列車列(最右)にあるときは「新規列車を末尾に追加」。[時刻表]-[列車を挿入]でフォーカス位置への挿入(空列車 1 本、`ressya/replaceRange` の deleteCount=0。原典 ECreateCmd_NewItem、複数選択中は不可)。
4. 列単位の切り取り/コピー/貼り付け/消去、通過・経由なし・当駅始発/止り・直通化/分断・運休、駅時刻挿入/削除、駅時刻変更+再実行、連続 1 分修正、並べ替え、列車番号で一本化、最小所要時間列車に移動、左へ/右へ — すべて §4.3 のキーと §6 の選択仕様に従い、`ressya/replaceRange`(または `ressya/swap`)コマンドに正規化して `executeCommand()` する。
5. ダイアログ確定後のフォーカスは**フォーカス移動モード**(下移動/右移動、ツールバートグル)に従う。下移動: 同列車の次の駅時刻行へ(発着駅の着→同駅の発)。右移動: 同行の次列車へ。
6. 差分更新: `ressya/replaceRange` → 該当列のみ cellSpec 再評価・部分再描画。`eki/*`・`syubetsu/*` → 全再構築(コマンド型ディスパッチ)。

#### ビュー間ジャンプ

- F8 = ダイヤグラムへ移動(フォーカスの駅・列車が見える位置で `diagram` タブを開く/アクティブ化)。
- フォーカス駅の駅時刻表を開く/駅のプロパティ/交差支障チェック(v0.8)= コンテキストメニュー([右クリック]は Web では有効化する。原典時刻表ビューの右クリック運用系コマンド群を含む)。

#### カスタマイズ時刻表(v0.6)

同じグリッド基盤で `customize: true` のビューとして開く。列 = CustomizeJikokuhyouContent(直通チェーン)、行 = 駅ごとの表示設定に従う拡張行(前列車情報・入線時刻等)。編集コマンドの大半は原典同様無効(`canExecute` が false を返す)。

### 3.5 コメントビュー(`comment`)

- `<textarea>`(等幅でない、路線プロパティのコメントフォント設定を反映)。Canvas 化しない唯一のビュー(プレーンテキストはネイティブ要素が最良)。
- 遅延コミット: 入力中は UI ローカル状態に保持し、**フォーカス喪失・タブ切替・保存操作の時点で** LF 正規化して `comment/set` コマンド化する(原典 LHINT_SUBVIEW_TO_ROOTDOC 相当)。Undo はコマンド単位。

### 3.6 運用系ビュー(v0.7)

すべて Worker の運用探索結果(導出キャッシュ)を購読する読み取り系ビュー + 時刻表へのジャンプで構成する。探索中は前回結果を表示し、ステータスバーにインジケータを出す。「運用更新の一時停止」トグルと F5 手動更新も原典どおり提供する。

#### 運用表(`operationTable`)— ダイヤ × 運用番号ごと

- **従来形式**: 1 列車 1 行のグリッド。列 = 列車番号/種別/列車名/始発側(駅名・番線・時刻)/方向矢印/終着側(同)。同一列車扱い接続は 1 行に併合。
- **箱ダイヤ形式**(ツールバートグル): 表示駅(駅設定 + 運用中列車の始終着駅)を縦に並べ、列車を水平線 + 着発時刻で描画、直接接続は縦線、出区○/入区△、経由なし区間は破線。
- 操作: 時刻表へ移動/移動して編集(初期文字列転送あり)、ダイヤグラムへ移動、コピー(テキスト)、CSV。

#### 運用一覧表 / 運用一覧図(`allOperationTable`)— 1 ビューモデル + 2 レンダラ

- 共通ビューモデル: `OperationTableContent` 群 + ソート(運番/出区駅/出区時刻/入区駅/入区時刻 × 末尾要素基準フラグ)+ 抽出条件。実装(ビューモデル + 導出ロジック)は共有するが、**表と図は別タブ**(記述子の `graphical` で区別。原典も WindowType 5/6 の別ウインドウ)。ツールバーの [表|図] トグルは「対応するタブへの切替(未オープンなら開く)」として動作する。
- 並び順・抽出条件は各ビューのプロパティダイアログで設定する(原典 CDlgAllOperationTableProp / CDlgAllOperationTable2ViewProp 相当。一覧図側は横軸表示範囲も含む。§2.2)。
- 一覧表レンダラ: 行 = 運用、列 = 運番/出区駅・時刻/→/入区駅・時刻 + 列車情報の繰り返し。[全列車を表示] トグル。操作: Enter/ダブルクリック = 運用表へ移動、F6 = 時刻表へ移動して出区駅作業編集(初期文字列のキー転送 §5.2)、F7 = 時刻表へ移動、F8 = ダイヤグラムへ移動(分析 §07 3.2)。
- 一覧図レンダラ: 行 = 運用、横軸 = 時刻。列車を種別線色の水平線分で描画、線上に列車番号等、始終着駅名略称(EkimeiDiaRyaku)表示。横軸ズームは ダイヤグラムと同じ離散ステップ。ダブルクリックで運用表または時刻表へ。
- CSV エクスポート(抽出条件ダイアログ付き)。

#### 入出区連携コード一覧(`inOutLinkCodeList`)

- 参照専用グリッド。列 = コード/入区側(方向・列車番号・種別)/→/出区側(同)/運用番号。iStatus≠2 の行は「無効」表示。行選択 → Enter で時刻表へ移動。

### 3.7 交差支障チェック(`crossingCheck`)(v0.8)

ダイヤ × 駅ごとに開く。判定は derive の純関数を Worker で実行。

```
+──────────────────────────────────────────────────────────────+
│ ツールバー: [再チェック] [ルール編集…]   ⚠ 編集後は再チェックが必要 │
+──────────────────────────────────────────────────────────────+
│ 1. 開通時隔  前:着・停車  時隔 0〜90秒                        │← ルール見出し行
│   ↓921M 普通  8:59:30  上り本線→2   30秒  ↓923M 快速 9:00:00 …│← 該当列車組
│ 2. 折り返し時間 [無効]                                        │
+──────────────────────────────────────────────────────────────+
```

- 原典の「自動更新されない(開き直しが必要)」仕様は、**[再チェック] ボタン + 陳腐化バナー**に置き換える: 列車編集コマンドが実行されたら結果を消さずに「⚠ ダイヤが変更されました。再チェックしてください」を表示する(明示実行の原則は 02_architecture §4.6 どおり維持)。
- 行選択 → Enter = 時刻表へ移動、F8 = ダイヤグラムへ移動。
- ルール編集は駅プロパティ配下の交差支障ルールダイアログ(From/To 番線集合の複数選択リスト、到着/出発・通過/停車、時隔下限〜上限、説明文)。

## 4. キーボード操作体系

キーボード操作の忠実な再現が既存ユーザ移行の鍵である(分析 §08 Tier2)。原典アクセラレータテーブル(分析 §04 5.4)を keydown ハンドラとしてそのまま移植する。

### 4.1 キーマップ 2 モードと代替バインド

ブラウザ予約キーとの衝突(02_architecture §9.4)に対し、次の方針を確定する。

1. **代替バインド(Alt 系)は全環境で常時有効**とする。原典バインドが効かない環境でも必ず操作できる。
2. **原典バインド(Ctrl 系)は PWA インストール時(`display-mode: standalone`)に追加で有効**とする。ブラウザタブ表示時、傍受不能キー(Ctrl+T/N/W 等)は諦め、傍受可能なもの(Ctrl+J/K/L 等)は `preventDefault` で奪って有効にする(奪えるかは実行時に判定せず、既知の傍受不能リストで静的に無効化する)。
3. キーマップはユーザ設定可能(設定ダイアログ、localStorage 保存、「既定に戻す」あり)。
4. メニュー・ショートカット一覧には**現在有効なバインド**を表示する。

### 4.4 連続入力モード(Ctrl+T / Alt+T)

原典 CWjkState_Renzoku の仕様を厳密に再現する(v0.4)。

- 入場条件: フォーカスが列車の駅時刻セルにあり、その位置より前に駅時刻が入力済みで、最下段でないこと。満たさなければ即終了。
- **分 2 桁のみ**で入力: 1 文字目 '0'〜'5'、2 文字目 '0'〜'9'。2 桁揃ったら直前駅時刻の「時」を補完し、直前より前になるなら +1 時間。駅扱が運行なしなら停車化 + 基準番線適用。1 打鍵ごとに `ressya/replaceRange` を実行(Undo 可能)。
- 編集中セルには `"%2d%-2s"`(直前駅の時 + 入力途中の分)を直接描画する。
- BackSpace: 入力途中なら 1 文字訂正 / 未入力なら前の駅時刻セルへ戻る。Esc: モード終了。終着駅で自動終了。
- モード中はセル選択禁止。使える追加コマンドは[時刻消去][通過][経由なし]のみ。他の構造変更が起きたら強制終了。
- モード中はステータスバーに「連続入力モード」を表示し、`aria-live` でも通知する。
- 入力は IME オーバーレイ input で受けるが、モード中は IME を無効化(`inputmode="numeric"`)する。

### 4.7 実装方式

- キーマップは `apps/web` の宣言テーブル `{commandId, primary, alternate, scope(view type), when(モード条件)}` で一元管理する。keydown ハンドラはアクティブビューのスコープ → グローバルの順にマッチし、マッチしたら `preventDefault()`。
- Playwright E2E(v0.4)はこのテーブルを読み、両モード(standalone / タブ)で全バインドを回帰テストする。

## 5. プロパティ編集 UI

### 5.1 `usePropEdit` フック

原典 NsPropEditUi2(CPropEditUi2)の StartEdit / OnUiChanged / EndEdit ライフサイクルを、ネイティブ `<dialog>` + React フォームフックとして再現する。UI ライブラリは使わない(02_architecture §1.2)。

```typescript
const {
  uiData, // UIData(フォーム状態。原典 UIData_Eki 等と同型)
  setField, // OnUiChanged 相当: 値設定 + フィールド単位の即時正規化
  blurField, // フォーカス喪失時の正規化(時刻 decode + 時補完はここ)
  errors, // フィールド別エラー(CheckUiData の結果)
  enable, // フィールド別活性フラグ(原典 bXxxEnable 群の導出)
  commit, // EndEdit 相当: 検証 → EditCommand 生成 → executeCommand → close
  cancel,
} = usePropEdit({
  target, // 編集対象(RosenFileData 内の参照 index 群)
  initialKeyString, // キー転送の初期文字列(§5.2)。省略可
  buildUiData, // StartEdit: target → UIData
  validate, // CheckUiData: UIData → errors(OK 押下時 + blur 時)
  buildCommand, // UiDataToTarget: UIData → EditCommand
});
```

確定仕様:

- ダイアログはすべて**モーダル** `<dialog>`(`showModal()`)。Esc = キャンセル、Enter = OK(textarea 内を除く)。開閉時にフォーカスを呼び出し元セルへ復元する。
- 検証エラーは (1) フィールド脇の赤字メッセージ、(2) OK 時は最初のエラーフィールドへフォーカス移動、で表示する。原典のメッセージ文言(例: 種別削除エラーの該当ダイヤ・方向表示)を踏襲する。
- 正規化のタイミングは原典どおり **blur 時 + OK 時**(タイプ中に書き換えない)。例: 駅時刻欄は blur で `decode` → 表示書式へ再整形。
- 複数選択編集(種別色等)は Nullable 値(「変更しない」)をフィールド型で表現する(CdColorPropNullable 相当: `Color | 'unchanged'`)。
- コミットは常に 1 ダイアログ = 1 コマンド(複数フィールド変更でも 1 Undo 単位)。
- **ダイヤ一覧ダイアログのみ即時反映方式**: OK/キャンセルを持たず、[新規作成][プロパティ][コピー][削除][上へ][下へ]の各ボタンがその場で個別コマンドを実行する(原典踏襲。Undo も個別)。

### 5.2 キー転送(CKeyinputSenderToModalDlg の代替)

グリッド上で文字・数字キーを押すと該当ダイアログが開き、押した文字が最初の入力欄に入っている——この操作感を次で再現する。

1. グリッドの IME オーバーレイ input が常時フォーカスを保持する。
2. printable キー押下(または IME 確定)で、その文字列を `initialKeyString` としてダイアログを開く。
3. ダイアログは対象入力欄(駅時刻なら着/発時刻欄、列車なら列車番号欄)に `initialKeyString` を設定し、**カーソルを末尾に置いてフォーカス**する。以降のタイプはそのまま続けられる。
4. 「時刻表へ移動して編集」(運用表 F6 等)でも同じ機構で初期文字列を渡す。

## 6. 選択・コピペ・Undo/Redo の操作仕様

### 6.1 選択モデル

- 選択の単位はビューごとに固定: 時刻表 = **列(列車)単位**、駅・種別 = **行単位**、駅時刻表・運用系 = セル(参照専用)。セル単位の編集選択は存在しない(原典踏襲)。
- 箱型選択(Shift+矢印 / ドラッグ)と非連続ランダム選択(Ctrl+クリック / Ctrl+Space)を併存させ、選択状態はビューモデルの `CaMuiSelect` 相当(選択 index 集合)で保持する。
- 選択 → コマンド生成は原典 ECreateCmd 5 種(NewItem / Focus / Sequence / Select / All)をビューモデルのヘルパとして移植する。複数選択への一括適用(通過・消去等)も原典どおり。
- 選択表示: 選択セルは色反転、フォーカスセルは点線枠(Canvas 描画)。

### 6.2 クリップボード

- **アプリ内クリップボード**(メモリ)を一次とする: 列車列 / 駅行 / 種別行のドメインオブジェクト(deep copy)+ 種別(kind)を保持。ブラウザタブをまたぐ共有はしない。
- コピー時に**システムクリップボードへ時刻表 CSV 互換テキストをミラー**する(`navigator.clipboard.writeText`)。表計算ソフトへの貼り付けを可能にする。
- 貼り付けは (1) アプリ内クリップボードに整合する内容があればそれを優先、(2) なければシステムクリップボードのテキストを CSV としてパース(原典 Ver2.02.05 のテキスト形式ペースト互換)。クリップボード読み取りは貼り付け操作時のみ(権限プロンプト対応)。
- 「時刻のみ貼り付け」「作業のコピー」「列車情報のコピー」はアプリ内クリップボード限定。

### 6.3 貼り付け移動量(パターンダイヤ入力)

原典セマンティクスを厳守する:

- 時刻表ビューのプロパティで移動量(秒)・列車番号移動量・号数移動量を設定。
- **貼り付けるたびに累積加算**(`prev += 移動量`)し、コピー/切り取りでリセット。
- 現在の累積値はステータスバーに常時表示し、クリックでビューのプロパティを開く。

### 6.4 Undo/Redo

- patch 方式(02_architecture §4.4)。UI 仕様:
  - 編集メニューに「元に戻す: {コマンド表示名}」「やり直し: {コマンド表示名}」を表示(コマンド型 → 日本語名のテーブル)。
  - Undo 深さ既定 100・設定可変。履歴パレット(一覧 UI)は作らない。
  - Undo/Redo 後のビュー更新はコマンド型ディスパッチ。フォーカスは影響列・行があればそこへ移動、なければ維持。
  - 連続入力モードの 1 打鍵 = 1 コマンド = 1 Undo 単位(原典どおり)。
- コメントビューの textarea 内はネイティブ Undo(Ctrl+Z)が効くが、コミット後はストア Undo に一本化される(フォーカスがビュー本体にあるときのみストア Undo を発火)。

### 6.5 変更状態と離脱保護

- 変更カウンタは原典仕様(保存 0 / 変更・Redo +1 / Undo -1 / 負から編集で INT_MAX)。カウンタ ≠ 0 のときタイトル・タブに `*` を表示。
- `beforeunload` で未保存時に離脱確認。加えて編集契機 60 秒間隔の OPFS 自動バックアップがあるため、強制終了でも復元可能(ホーム画面 §1.6)。
- ダイヤ削除等でタブが自動クローズされる際は確認を出さない(Undo で戻せるため)。

## 7. アクセシビリティ・日本語 UI・モバイル対応

### 7.1 アクセシビリティ

Canvas グリッドの構造的制約(スクリーンリーダー・ブラウザ内検索不可)は受容し(02_architecture §9.3)、次で部分補償する。

- **フォーカスセルの aria-live 通知**: グリッドのコンテナに `aria-live="polite"` の可視外リージョンを併設し、フォーカス移動ごとに「品川 発 9時55分 列車 1021M 快速」の形式で通知する。モード遷移(連続入力開始/終了)、コマンド実行結果(「3 列車を通過に変更」)も通知する。
- **列車番号検索**(Ctrl+F 傍受、原典の検索ダイアログバー相当): 時刻表・ダイヤグラム・運用系ビューにビュー内検索バーを表示し、列車番号の部分一致でフォーカス移動 / スジへスクロールする。ブラウザ検索が効かない補償の中核。
- シェル UI(メニュー・ツリー・タブ・ダイアログ・ツールバー)は WAI-ARIA Authoring Practices のパターン(menubar / tree / tablist / dialog)に準拠し、全操作をキーボードのみで完結可能にする。
- Canvas は `role="grid"` + `aria-rowcount/colcount` を持つ単一要素とし、フォーカスセルのみ `aria-activedescendant` 用の仮想ノードで表現する(全セルの DOM 化はしない)。
- 色のみに依存する状態表示を避ける: 運休 = 灰背景 + 通知文言、選択 = 反転 + フォーカス枠。コントラストはファイル由来の色指定(種別色等)には介入しない(互換優先)が、シェル UI は WCAG AA を満たす。
- High-DPI: `devicePixelRatio` に応じた Canvas バックバッファで文字を鮮明に描画する。

### 7.2 日本語 UI・フォント

- UI 文言は日本語のみ(i18n 機構は導入しない)。原典のメニュー・ダイアログ・エラーメッセージの文言を踏襲する(特に oud 書き出しの機能喪失警告、種別削除エラー)。
- 記号(ﾚ・||・・・・----・○・====・↳・↴・●)は原典の文字をそのまま使用する(画像化しない。CSV・コピーテキストとの一貫性のため)。
- フォント: ファイル内のフォント指定(既定 Meiryo UI)は保持・書き戻しつつ、描画時は `"{指定フォント}", "Meiryo UI", "Yu Gothic UI", "Hiragino Sans", sans-serif` のフォールバックスタックに解決する。非 Windows 環境でのメトリクス差は列幅計算を実測(`measureText`)ベースにすることで吸収する。
- 縦書き(列車名・備考)は Canvas に 1 文字ずつ縦組み描画(原典 CDcdTextboxV3 相当)。CSS `writing-mode` は使わない(Canvas 内のため)。

### 7.3 モバイル対応

v0.1 ビューアの閲覧体験を第一級サポートとし、編集はキーボード前提のためベストエフォートとする(02_architecture §8.3)。

| 項目               | 仕様                                                                                                                                                                              |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| レイアウト         | §1.7 の < 768px レイアウト。タブバー横スクロール、ドロワーツリー                                                                                                                  |
| ダイヤグラム       | 1 本指ドラッグ = パン、ピンチ = ズーム(離散ステップへスナップ: X=30 分単位 / Y=1/10 単位の最近傍)、タップ = スジ選択(ヒットマージン 12px に拡大)、選択後の再タップ = 時刻表へ移動 |
| 時刻表・各グリッド | スワイプ = スクロール(慣性あり)、タップ = セルフォーカス、ダブルタップ = プロパティ表示(v0.1 では読み取り専用ダイアログとして表示)                                                |
| 駅時刻表           | スマホ最重要ビュー。縦 1 カラムで時×分を表示                                                                                                                                      |
| 編集               | ソフトウェアキーボード + ダイアログ経由で一応可能(連続入力モード・ショートカット系は非対応と明記)                                                                                 |
| PWA                | インストール可能、オフライン閲覧、ファイルは共有シート / input[type=file] で受け取る                                                                                              |

将来のタッチ最適化編集(スジのドラッグ等)は原典に前例がない自由設計領域であり、本設計の範囲外とする。

## 付録: 原典との意図的な差分一覧

互換を最優先しつつ、Web として合理的な範囲で次の差分を採る(いずれも既存操作の置換ではなく追加・昇格)。

| #   | 差分                                                                                     | 理由                                                                                                                 |
| --- | ---------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| 1   | MDI → タブ型単一作業領域                                                                 | ブラウザウインドウ内の MDI は操作性が悪い。DocStr 同型のビュー記述子で二重オープン防止・自動クローズの原典挙動は維持 |
| 2   | 運用一覧図・入出区連携コード一覧をツリー常設項目化                                       | 右クリック限定の隠し導線は発見性が低い                                                                               |
| 3   | ダイヤグラムに Shift+ホイール横スクロール / Ctrl+ホイール離散ズーム / ドラッグパンを追加 | 表示専用ビューのため既存操作と衝突しない                                                                             |
| 4   | 交差支障チェックの「開き直し更新」→ [再チェック] ボタン + 陳腐化バナー                   | 明示実行の原則は維持しつつ、タブ UI では開き直しが不自然                                                             |
| 5   | Undo 深さ 8 → 100(設定可変)                                                              | patch 方式でメモリコストが低い                                                                                       |
| 6   | 代替キーバインド(Alt 系)の常時有効化                                                     | ブラウザ予約キー対策(§4.1)                                                                                           |
| 7   | コピー時のシステムクリップボードへの CSV テキストミラー                                  | 表計算ソフト連携(原典のテキスト形式ペーストと対)                                                                     |
| 8   | 列車番号検索をダイアログバー → ビュー内検索バー(Ctrl+F)                                  | Canvas でブラウザ検索が効かないことへの補償                                                                          |
| 9   | WindowPlacement を UI に使わない(透過書き戻しのみ)                                       | Web のタブ状態と Windows のウインドウ配置は概念が異なる(02_architecture §4.5)                                        |
| 10  | 印刷・WinDIA・外部時刻表インポートの非対応/後回し                                        | Tier4(分析 §08)                                                                                                      |
