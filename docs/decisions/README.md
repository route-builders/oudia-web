# アーキテクチャ決定記録 (Architecture Decision Records)

プロジェクトの重要な技術的決定を記録する ADR を格納するディレクトリ。

## ADR とは

重要な決定について「**コンテキスト**(なぜ必要だったか)・**決定**(何を決めたか)・**理由**(なぜそれを選んだか)・**影響**」を記録する軽量ドキュメント。将来「なぜこうなっているのか」を辿れるようにするためのもの。

## ステータスの意味

- **Proposed**: 提案段階
- **Accepted**: 承認済み(実装中または実施済み)
- **Deprecated**: 非推奨
- **Superseded**: 別の ADR に置き換えられた

## 新しい ADR の作成方法

1. [adr-template.md](./adr-template.md) をコピーし、`adr-XXXX-{タイトル}.md` として作成(XXXX は連番)
2. テンプレートに従って記述
3. この README の一覧に追加

## いつ ADR を書くか

- 技術スタック・ライブラリの選択、および **design/02_architecture.md の確定事項を変更するとき**(必須)
- 原典と意図的に挙動を変える決定(互換性に関わるもの)
- データモデル・ファイル形式の扱いに関する重要な設計判断
- パフォーマンス・セキュリティに影響する設計決定

書かなくてよいもの: 実装の詳細、一時的な実験、自明な決定。

## 設計ドキュメントとの関係

`docs/design/` は「現在の設計の全体像」(常に最新に保つ)、`docs/decisions/` は「決定の履歴」(追記のみ、書き換えない)。設計を変更するときは、ADR を書いてから design/ 側を更新する。
