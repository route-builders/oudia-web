# 08. マニュアルからの機能インベントリ(ユーザ視点の全機能一覧)

## 概要

本ドキュメントは、以下の一次資料から OuDiaSecond ver 2.06.23 の「ユーザから見える機能」を網羅的に棚卸ししたものである。

- `origin/DiagramEdit/manual/oudia_manual/` — HTMLマニュアル全章(CP932)。**注意: このマニュアルは本家 OuDia (take-okm作、~Ver1.02.05/2017) のものがそのまま同梱されており、OuDiaSecond の拡張機能(番線・運用・交差支障など)は記載されていない。**
- `origin/OuDiaSecond変更箇所.txt` — OuDiaSecond(作者 diagram_mania)が本家に対して加えた全変更の履歴(Ver1.00〜2.06.23)。OuDiaSecond 拡張機能の唯一のまとまった文書。
- `origin/DiagramEdit/DiagramEdit.txt` — 本家 OuDia のビルド手順・SVNタグ履歴(機能情報は少ない)。
- `origin/ReadMe.txt` — OuDiaSecond のライセンス告知(GPLv3、VS2019、Windows 11 で開発)。
- `origin/DiagramEdit/manual/sample2.oud2` — OuDiaSecond 形式サンプル(`FileType=OuDiaSecond.1.17`、UTF-8 BOM付き)。

したがって機能は2層で捉える必要がある: **(A) 本家OuDiaのコア機能(マニュアルに詳述)** と **(B) OuDiaSecond拡張(変更箇所.txtから復元)**。

## 1. チュートリアルから見た基本ワークフロー

出典: `manual/oudia_manual/c02_usersguide/c01_tutorial/`(2.1章)。

### 1.1 画面の基本構成

- メインウインドウは中央のバーで左右に分割。左が **『路線ビュー』**(ツリー形式、エクスプローラ風)、右が **『作業領域』**(MDI)。
- 路線ビューの初期アイコン: `[路線]`・`[駅]`・`[列車種別]`・`[ダイヤ]`。ダイヤを追加すると `[(ダイヤ名)]` の下に `[下り時刻表]`・`[上り時刻表]`・`[ダイヤグラム]` の3アイコンが現れる。ほかに `[コメント]` アイコンがある。
- OuDiaSecond ではさらにツリーに **駅時刻表一覧・運用表/運用一覧・運用一覧図・入出区連携コード一覧** の項目が追加されている(変更箇所.txt Ver2.02/2.03/2.04/2.05、`ViewRosen/CRosenViewTreeCtrl.cpp`)。

### 1.2 新規作成ワークフロー(チュートリアル 2.1.2 の順序)

1. **新規作成** — `[ファイル]→[新規作成]`。全データが初期状態になる。
2. **路線名を設定** — `[ファイル]→[路線ファイルのプロパティ]`(=路線アイコンのダブルクリック)の[路線]タブで[路線名]を入力。
3. **駅の入力** — 路線ビュー`[駅]`クリックで『駅ビュー』(グリッド形式)を開き、`[編集]→[駅を挿入]`(Ctrl+Ins / 最下行ダブルクリック / 最下行でそのまま駅名タイプ開始)で[駅のプロパティ]ダイアログから起点→終点の順に追加。終着駅は駅時刻形式を「下り着時刻」にするのが推奨。
4. **列車種別の入力** — 路線ビュー`[列車種別]`で『列車種別ビュー』を開き同様に追加。初期状態で種別『普通』が登録済み。
5. **ダイヤを新規作成** — `[ファイル]→[ダイヤ一覧]`(=`[ダイヤ]`アイコンのダブルクリック)→[新規作成]→ダイヤ名(例: 平日/土休日)。1路線ファイルに複数ダイヤを格納できる。
6. **列車の入力** — `[下り時刻表]`/`[上り時刻表]`で『時刻表ビュー』を開き、(a)[列車のプロパティ](列車番号・種別・列車名・備考・空行)を設定 → (b)始発駅から順に[駅時刻]ダイアログで駅扱・着/発時刻を入力。
7. **列車入力の注意** — 全区間に少なくとも下り・上り各1本の「各駅停車」が必要(区間分割でも可)。ダイヤグラムの駅間の縦幅は各駅停車の最速所要時間 **『駅間最小所要秒数』** から決まり、これはダイヤグラムビューを開いたときと`[表示]-[更新]`時のみ再計算される。各停の無い区間は通過列車に通過時刻を入れることで補える。
8. **コメント入力** — `[コメント]`アイコン→『コメントビュー』(メモ帳同等の操作)。
9. **保存** — `[ファイル]→[名前を付けて保存]`。路線ファイルには路線名・全駅・全種別・全ダイヤ・全列車・コメントが含まれる。

### 1.3 閲覧・出力ワークフロー(2.1.1)

- ファイルを開く(メニュー / エクスプローラのダブルクリック / D&D)→ 時刻表ビュー表示 → ダイヤグラムビュー表示(時刻表からは `[駅時刻]-[ダイヤグラムへ移動]`=F8 でフォーカス位置に同期して開ける。逆にダイヤグラム上の列車線ダブルクリックで時刻表ビューへ)→ 印刷/印刷プレビュー。

### 2.2 路線ビュー(3.2章)

ツリー形式。各アイコンのクリック/ダブルクリックで対応ビュー・ダイアログを開くランチャー。

### 2.3 駅ビュー(3.3章) — `ViewEki/`

- グリッド形式ビュー。編集単位は「駅(横一列)」。
- [編集]: 元に戻す/やり直し/切り取り/コピー/貼り付け/消去/**駅を挿入**/**駅の反転**(全駅順序反転、下り列車⇔上り列車が入れ替わる)/駅のプロパティ。
- [ファイル]: **路線ファイルの組入れ**・**路線ファイルの切り出し**(§4参照)。
- OuDiaSecond拡張: 分岐駅・環状線設定の表示、右クリックから番線設定、複数選択(一続き)での切り取り・消去(Ver2.06.01)、**表示設定モード**(表示列を絞る、Ver2.03.01)、ヘッダー二行化(Ver2.06.21)、テキスト形式ペースト(Ver2.02.05)。

### 2.4 列車種別ビュー(3.4章) — `ViewRessyasyubetsu/`

- グリッド形式。編集単位は「種別(横一列)」。元に戻す/やり直し/切り取り/コピー/貼り付け/消去/列車種別を挿入/**上へ・下へ**(順序入替)/プロパティ。
- その種別を使う列車が存在する場合、切り取り・消去は不可。
- OuDiaSecond拡張: 種別背景色確認欄(Ver1.03)、**親種別**表示欄(Ver1.04)、隠し種別欄(Ver2.06.15)、種別番号欄2桁(Ver2.01)、複数入替(Ver2.06.01)。

### 2.5 時刻表ビュー(3.5章) — `ViewJikokuhyou/`

最も機能が多いビュー。編集単位は「列車(縦一列)」。

- **[ファイル]**: 時刻表CSVファイルへエクスポート(§4)。本家にあったCSVインポートは OuDiaSecond Ver2.01 で削除済み(`ID_FILE_IMPORT_JIKOKUHYOUCSV` は `DiagramEdit.rc` の String Table にのみ残存し、MENUITEM・ハンドラは存在しない)。
- **[編集]**: 元に戻す(Ctrl+Z)/やり直し(Ctrl+Y)/切り取り(Ctrl+X)/コピー(Ctrl+C)/貼り付け(Ctrl+V)/消去(Del)/**時刻のみ貼り付け**(直通化の手動方式)/すべて選択。複数列車の箱選択(Shift+移動、ドラッグ)にも対応。
- **[時刻表]**: 列車のプロパティ / 列車を挿入 / **フォーカス下移動・右移動**(フォーカス移動モード切替) / **最小所要時間列車に移動**(入力ミス発見用) / **並べ替え**(駅扱・停車駅時刻・列車種別・備考の4方式。選択列車のみの並べ替えも可) / **列車番号で一本化**(全自動直通化) / 時刻表ビューのプロパティ。
- **[駅時刻]**: 駅時刻のプロパティ / 時刻消去 / **通過**(Ctrl+'-'、時刻削除) / **通過-停車**(Alt+'-'、時刻維持でトグル) / **経由なし**(Ctrl+Shift+'-') / **当駅始発** / **当駅止り** / **直通化**(自動方式) / **分断** / **連続入力**(Ctrl+T) / **駅時刻を挿入・削除**(時刻を1駅ずつ上下にずらす) / **駅時刻変更...**・**駅時刻変更の再実行**(Ctrl+ピリオド ※後述) / **連続1分修正**(-1分し次へ=Ctrl+J、フォーカスを次へ=Ctrl+K、+1分し次へ=Ctrl+L 等6コマンド) / ダイヤグラムへ移動(F8)。
- **[表示]**: 通過駅の駅時刻を表示 / 全時刻を表示。
- OuDiaSecond拡張(変更箇所.txtより): 秒単位表示・任意秒移動(±n秒)・**基準運転時分機能**(種別ごとの標準所要時間との比較表示、「基準運転時分に合わせる」コマンド、ステータスバーへの差分表示=Ver2.06.22)・番線編集モード・**カスタマイズ時刻表**(市販時刻表風表示、Ver2.01)・運用番号欄・始発/終着駅名と駅作業欄(画面上部固定)・路線外発着欄・コロン付き時刻表示・列車番号検索(Ver2.05.01)・「左へ」「右へ」(列車順入替、Ver2.06.01)・列車番号/号数のコピペ加算(Ver1.04)・運休設定表示(Ver2.06.15)。

### 2.6 ダイヤグラムビュー(3.6章) — `ViewDiagram/`

- 列車線(スジ)描画。列車線ダブルクリック→時刻表ビュー、駅名ダブルクリック→駅のプロパティ。
- [表示]: 横軸方向縮小・拡大 / 縦軸方向縮小・拡大 / 縦軸方向リセット / 横軸目盛を細かく・粗く(1,2,5,10,15,20,30,60分) / 列車番号の表示 / 列車名の表示 / 下り列車の表示 / 上り列車の表示 / 一般駅の駅名を表示しない / **停車駅を明示**(列車線上に○印。1分以上停車の駅には付かない。種別プロパティで種別単位に無効化可) / **更新**(駅間最小所要秒数の再計算+再描画) / ダイヤグラムビューのプロパティ。
- 描画仕様: 駅間の縦幅=駅間最小所要秒数。横軸は既定0:00起点24時間(起点時刻は路線プロパティで変更可、横軸表示範囲は起点時刻をまたげない)。駅規模=主要駅は太横線。列車情報(列番・列車名・号数)の表示位置は駅プロパティで制御。
- OuDiaSecond拡張: **在線表**(駅の番線ごとの在線を横帯で表示、Ver1.02)・折り返し接続線・運用番号表示(Ver1.03)・路線外発着表示(Ver1.04)・ダイヤ背景色/個別背景色(Ver1.02/2.03)・パターンダイヤプレビュー(Ver2.06.18)・ダブルバッファリング等の高速化(Ver2.04.02)。

### 2.7 コメントビュー(3.7章) — `ViewComment/`

メモ帳同等: 元に戻す/切り取り/コピー/貼り付け/消去/検索/次を検索/置換/すべて選択。

### 2.8 グリッド形式ビュー共通仕様(3.9章)

駅・列車種別・時刻表(および OuDiaSecond の各グリッド系ビュー)に共通。フォーカスセル、矢印キー追従スクロール、PageUp/Down・Home/End、ホイール、**複数セルの箱型選択**(Shift+移動/ドラッグ)、**ランダム選択**(Ctrl+クリック、Ctrl+Space)、複数選択への一括編集適用、複数選択時のプロパティダイアログ使用(本家Ver1.02.02)。

## 5. 設定項目(2.4章)

駅名欄の幅(全角、最大29)/時刻表の列車の幅(半角4〜6、OuDiaSecondは〜9)/ダイヤグラム起点時刻/ダイヤグラムの既定の駅間幅(1〜30分、支線のある路線用)/ダイヤグラムビューでの停車駅明示。いずれも路線ファイルのプロパティまたはビューのメニューから。

## 6. WinDIA 連携(2.2章 — 本家のみ)

本家 OuDia は WinDIA(.dia)の読み書きに対応(制約: 1ダイヤのみ、種別24まで、16色、略称半角4文字、境界線・経由なし非対応)。**OuDiaSecond は Ver1.02 で WinDIA 入出力を削除した**(`CDiagramEditDoc` から削除、変更箇所.txt)。Web再実装でも対応不要と判断できる。

## 9. 機能重要度の所感(Web再実装の取捨選択の参考)

マニュアル・チュートリアルでの扱いの大きさ、および変更履歴での言及頻度からの評価。

### Tier 1 — コア(これが無ければ成立しない)

- データモデル: 路線/駅/種別/ダイヤ/列車/駅時刻(駅扱+着発時刻)。
- 路線ビュー(ツリー)+駅・種別・時刻表・ダイヤグラムの4ビュー。
- 時刻表ビューのセル編集(ダイアログ+直接キー入力)、列車単位のコピー/ペースト/消去、Undo/Redo。
- ダイヤグラム描画(駅間最小所要秒数による縦配置、種別ごとの線色/スタイル、拡大縮小、時刻表⇔ダイヤグラム相互ジャンプ)。
- oud2 ファイルの読み書き(テキスト形式、UTF-8)。旧 oud 読み込みも実装容値は高い(既存資産)。

### Tier 2 — 入力効率機能(本ソフトの価値の中核。マニュアル2.3章が最大の章)

- 連続入力モード、繰上げ/繰下げ、時の補完、連続1分修正、駅時刻変更+再実行、パターンダイヤ連続貼り付け、フォーカス移動モード、並べ替え、直通化/分断/当駅止り・始発、最小所要時間列車に移動。
- これらはショートカットキー前提の設計であり、Web版でもキーボード操作の再現が価値の大半を占める。

### Tier 3 — OuDiaSecond の差別化機能(利用者がOuDiaSecondを選ぶ理由)

- 番線+在線表、運用機能(駅作業・運用接続・運用表・運用一覧・箱ダイヤ)、路線外発着、秒単位時刻、基準運転時分、カスタマイズ時刻表、駅時刻表。変更履歴の大半がこの領域の改良に費やされており、OuDiaSecondユーザの中心的関心事と推定される。ただし実装は相互に深く絡む(運用⇔番線⇔駅作業⇔在線表)ため、段階導入するなら「番線→運用→箱ダイヤ/一覧」の順が依存関係に沿う。

### Tier 4 — 周辺・省略候補

- 印刷/印刷プレビュー(Webではブラウザ印刷・PDF出力で代替)、WinDIA入出力(OuDiaSecond自身が廃止済み)、時刻表CSVインポート(OuDiaSecond自身が Ver2.01 で廃止済み。エクスポートのみ残存)、外部時刻表インポート(特定事業者サイト依存・スクレイピング的、法的にも別検討)、交差支障チェック・入出区連携コード・パターンダイヤプレビュー・隠し種別・運休扱い(上級者向け。後回し可)、ウインドウ配置復元(Web では別概念)、自動バックアップ(localStorage/IndexedDBで簡略化可)。

## 10. Web再実装に向けた論点

1. **マニュアルの欠落**: OuDiaSecond拡張機能には整備されたユーザ文書がない。UI仕様は `ViewXxx/` のソースと変更箇所.txtから復元する必要がある(特に駅作業ダイアログ、カスタマイズ時刻表、交差支障)。
2. **MDI+メニュー動的切替**: 「アクティブビューによってメインメニューが変わる」設計はWebでは不自然。ビューごとのツールバー/コマンドパレットへの再設計が妥当。ペイン構成(左ツリー+作業領域)自体はWebでも踏襲しやすい。
3. **キーボード操作が本体**: グリッドのフォーカスセル・箱選択・ランダム選択、Ctrl+J/K/L、Ctrl+ピリオドの再実行、連続入力モード、テンキー'-'等。ショートカット網の忠実な再現が既存ユーザ獲得の鍵。
4. **クリップボード**: 列車/駅/種別のアプリ内独自フォーマット+テキスト形式ペースト(Ver2.02.05)がある。Web では Clipboard API の権限・フォーマット制約を考慮し、アプリ内クリップボードで代替+テキスト互換を検討。
5. **駅間最小所要秒数の再計算タイミング**: 「ビューを開いたとき/[更新]時のみ再計算」という遅延仕様は性能対策。Web版ではリアクティブに再計算するか、同じ遅延方式を踏襲するかの設計判断が要る。
6. **単位系**: 内部は秒単位(Ver1.00以降)、表示は丸め設定(着/発別)+2400表示。時刻は 0:00〜(24h+α) で日跨ぎ・起点時刻(ダイヤグラム左端)の概念がある。
7. **分岐・環状の表現**: 「同じ駅を駅リストに複数回登場させる」モデル(分岐駅設定・環状線設定・反転駅)が、番線・運用・交差支障の調整処理(`adjustBrunchLoop*`)と絡み最大の複雑性源。Web版のデータモデル設計で最初に決めるべき点。
8. **Windows依存**: MFC Doc/View、GDI描画(DcDrawLib)、CHMヘルプ、プリンタダイアログ、iniファイル/ウインドウ配置。描画は Canvas/SVG に置換、印刷はPDF生成に単純化できる。
9. **文字コード**: oud(CP932)読み込み互換を持つなら、ブラウザでの Shift_JIS デコード(TextDecoder('shift_jis'))が必要。oud2 は UTF-8 BOM 付きで問題ない。
10. **単純化できる点**: WinDIA、外部時刻表インポート、CHM、MDIウインドウ整列コマンド、プリンタ余白設定。逆に **Undo/Redo(編集コマンド)・ファイル形式互換・運用接続アルゴリズム** は簡略化するとユーザ価値を失う。
