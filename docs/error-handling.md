# エラー処理・ロギング規約

実行時の障害に対する方針を定める。ファイル読込エラーの体系は [design/04_file-io.md](./design/04_file-io.md) §3.7 が正であり、本書はそれ以外(アプリ実行時)を含む全体の規約を扱う。

## 0. 基本原則

1. **ユーザのデータを失わないことが最優先**。エラー時も編集内容(ストア + OPFS バックアップ)を可能な限り保全する
2. **黙って握りつぶさない**。ユーザ操作起点の失敗は必ずユーザに見える形で通知する
3. **クライアント完結**。エラー情報を外部サーバへ自動送信しない(テレメトリなし)。ユーザが明示的にコピーして報告する形のみ

## 1. エラーの分類と対応

| 分類 | 例 | 対応 |
|---|---|---|
| **ファイル読込エラー** | FileType 不正、必須キー欠落 | format 層の結果型(負コード + 詳細蓄積。design/04 §3.7)。ダイアログで理由と対処を提示 |
| **ファイル書込エラー** | FSA API の権限喪失、ディスクフル | 書込前の OPFS バックアップを保証したうえで、ダイアログで再試行/別名保存を提示 |
| **ストレージ障害** | OPFS 書込失敗、QuotaExceededError | バックアップ機能の劣化を**ステータスバーに常時表示**(以後の編集は継続可)。localStorage 破損は既定値で再初期化し通知 |
| **コマンド実行時例外** | レデューサ内の予期せぬ throw | `executeCommand()` で捕捉。**patch 未適用のままロールバック**(produceWithPatches は例外時に元 state を保つ)。履歴に積まず、エラートーストで通知 |
| **Worker 障害** | 運用探索のクラッシュ・応答なし | タイムアウト(既定 30 秒)で Worker を再生成。運用系ビューは前回の導出結果を表示し「更新失敗」バナーを出す |
| **描画例外** | レンダラ内の throw | 該当フレームを捨てて背景のみ描画 + トースト。連続 3 回で該当ビューをエラー表示に切替 |
| **React レンダリング例外** | コンポーネントの throw | Error Boundary で捕捉(§2) |

## 2. Error Boundary の粒度

- **タブ(ビュー)単位**に Error Boundary を置く。1 ビューのクラッシュで他ビュー・ストア・バックアップを巻き込まない
- ビュー内のエラー表示には「再読み込み」「エラー詳細のコピー」ボタンを置く
- アプリルートにも最終防衛の Boundary を置き、「バックアップは保全されている」旨と復元手順を表示する

## 3. ユーザ通知 UI の使い分け

| UI | 用途 |
|---|---|
| **ダイアログ(モーダル)** | ユーザの判断が必要なもの(読込失敗の詳細、別名保存の提案、クラッシュ復元の提案) |
| **トースト(自動消滅)** | 操作は継続できる一時的な失敗(コマンド失敗、コピー失敗) |
| **ステータスバー常時表示** | 継続中の劣化状態(バックアップ無効、Worker 停止中) |

通知文には (a) 何が起きたか、(b) データへの影響、(c) ユーザが取れる行動、を含める。技術的詳細は「詳細」折りたたみに入れる。

## 4. ロギング

- **開発ビルド**: `console` へ自由に出力してよい(ただしコミット前に意図的なログか確認)
- **本番ビルド**: `console.error` / `console.warn` のみ許可。加えてアプリ内**リングバッファ(直近 500 件、メモリのみ)**に記録し、エラーダイアログの「エラー詳細のコピー」で clipboard へ出力できるようにする(GitHub Issue 報告用)
- ログにファイル内容・路線データ等のユーザデータを**含めない**(パス名・ファイル名は含めてよい)
- ログ形式: `[時刻] [パッケージ名] メッセージ`(構造化は不要。個人開発の規模に合わせ簡素に保つ)

## 5. コーディング上のルール

- format / domain / derive の**純関数層は原則 throw しない**。失敗し得る操作は結果型(`{ ok: true, value } | { ok: false, error }` または design/04 のエラーコード体系)で返す
- throw を許可する層: app のインフラ操作(FSA API 等、例外ベースのブラウザ API を薄くラップする箇所)と、「到達したらバグ」の不変条件違反(`assertNever` 等)
- `catch` して何もしないことは禁止。無視する場合は理由コメントを付ける:
  ```ts
  } catch {
    // AbortError: ユーザがファイルピッカーをキャンセルした場合は何もしない
  }
  ```
- エラーメッセージは日本語で、原典のダイアログ文言がある場合はそれを踏襲する(分析 §08 参照)

## 6. クラッシュ復元との関係

エラー処理は [design/04_file-io.md](./design/04_file-io.md) §7.6 の OPFS 自動バックアップを前提とする。「どんな例外経路でも、直近 60 秒以内のバックアップより古い状態にデータが戻ることはない」を実装の不変条件とし、M2 の E2E(roadmap M2 完了条件 4)で検証する。
